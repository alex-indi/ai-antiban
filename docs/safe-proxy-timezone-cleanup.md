# Безопасное восстановление прокси и TZ

База аудита: `origin/main`, `afbfa9df3fa34ad64078f1a50f2e0df07dad0ce1`.
Ветка: `fix/safe-proxy-timezone-cleanup`. Приложение на рабочем Mac не запускалось.

## Аудит побочных эффектов

| Вход / момент | ОС, хранилище | Прежняя запись и очистка | Риск и изменение |
|---|---|---|---|
| Включение PAC | Windows, WinINet | `AutoConfigURL`, `ProxyEnable`; удаление URL, восстановление сокращённого `ProxyServer` | Журнал исходных типов/байтов и отсутствия; восстановление каждого изменённого значения по совпадению |
| PAC chaining | Windows | `ProxyServer` сводился к одному адресу, восстановление теряло карту протоколов | `ProxyServer`/`ProxyOverride` не записываются; входят в контрольный контекст `ProxyEnable`; несовместимые upstream отклоняются |
| Включение/выключение PAC | macOS, каждый сетевой сервис | networksetup; выключение PAC на всех сервисах и копирование одного HTTP/HTTPS proxy | SystemConfiguration: стабильный service ID и отдельный plist-ключ, точное отсутствие/тип; изменяются только PAC URL, PAC enable и необходимые HTTP/HTTPS enable |
| Смена сети, сон, VPN | обе | Фоновый refresh захватывал настройки повторно | Автоматическая перезапись прекращена; новый сервис/внешнее изменение не присваиваются при повторном enable |
| Запуск, отключение, force cleanup | Windows, HKCU Environment | Безусловное удаление proxy, TZ, LANG, LC_* | Миграция без доказуемого владения ничего не удаляет; новых глобальных записей нет |
| Интеграция GUI | macOS, launchd | setenv и безусловный unsetenv, включая чужой TZ | Глобальная интеграция удалена; используются конфиги ИИ-клиентов/профили; старые значения без журнала сохраняются |
| Включение CLI/IDE и TZ | обе, Claude/Gemini, VS Code/Cursor/Windsurf/VSCodium/Antigravity | Пересериализация JSONC, удаление группы полей по одному localhost-значению | Снимок отдельных ключей, точечная правка исходного текста, проверка каждого поля при восстановлении |
| Профили shell/PowerShell | обе, zshenv/zshrc/bash_profile/$PROFILE | Маркированный блок; PowerShell else удалял чужие переменные | Нет ветки удаления env; только точные отдельные строки маркеров; журнал блока, сохранение внешних правок/BOM/CRLF/прав |
| Нормальный выход и сигналы | обе, app/cleanup | Общая разрушительная очистка, повторные вызовы | Обе области восстанавливаются с журналом; повторный вызов идемпотентен |
| Panic, abort, kill, сбой питания | обе | Синхронная очистка в panic hook, RAM-снимок терялся | Panic hook не меняет ОС и не захватывает блокировки; durable intent восстанавливается при следующем запуске/`--cleanup` |
| Обновление | обе, updater | Вызывалась прежняя общая очистка | Существующие точки выхода вызывают безопасное восстановление обеих областей; алгоритм обновления сохранён |

## Модель владения

`owned_settings` хранит версию схемы, идентификатор свойства, исходное `Option<Value>`,
последнее установленное значение и незавершённое намерение. `None`, JSON null,
пустая строка и DWORD 0 различаются. Повторное включение обновляет ожидаемое
значение, сохраняя первоначальный baseline. При незавершённом обновлении
сохраняются оба возможных собственных состояния. Неизвестная версия, повреждение
журнала и невозможность получить блокировку приводят к отказу от записи.

Намерение сохраняется до изменения ресурса через временный файл в том же каталоге,
sync и атомарную замену; Unix также синхронизирует каталог. Журнал блокируется
между процессами. Восстановление выполняется в обратном порядке: сначала листовые
поля, затем созданные пустые контейнеры. Запись, не изменявшая значение, не создаёт
владения. Изменения пользователя сохраняются даже при совпадении localhost-порта.
Ошибка одного ресурса не блокирует остальные; ошибки и конфликты остаются в журнале.
При сбое после восстановления значения повторный проход безопасен.

Журнал: macOS `~/Library/Application Support/Zastava/owned-settings-v1/state.json`,
Windows `%LOCALAPPDATA%\Zastava\owned-settings-v1\state.json`.
На Unix каталог имеет права 0700, журнал 0600. На Windows каталог получает ACL
текущего SID без наследования. На macOS собственный каталог исключается из Time
Machine через `tmutil addexclusion` до сохранения секретов; при отказе изменения
не применяются. Журнал не включается в экспорт Claude или диагностические отчёты.
URL и credentials не выдаются в ошибках и результатах восстановления.

`disable_all_sysproxy()` восстанавливает системную область; CLI/IDE имеют отдельную
область. Завершение, обновление и `--cleanup` восстанавливают обе области. Результаты
содержат статусы «восстановлено / нет владения / конфликт / ошибка / неизвестно».
Неуспешное восстановление даёт ненулевой код `--cleanup`; NSIS не выполняет
запасного глобального сброса. Включение CLI возвращает сведения о неуспешных целях.

## PAC chaining и Throne

Существующий генератор PAC и маршрутизация ИИ не изменялись. Поддерживается прежняя
цепочка через один HTTP upstream, в том числе локальный HTTP-порт Throne. TUN и
настройки Throne/DNS/VPN не записываются. Снимок `ProxyServer` не заменяется одним
адресом при выходе; он вообще не переписывается. На macOS host/port/auth и исключения
не записываются; для временного отключения HTTP/HTTPS сохраняется контрольный контекст.
Если VPN изменил URL/флаг/контекст после включения, восстановление оставляет его выбор.

Различные HTTP/HTTPS upstream, разные upstream сервисов и аутентифицируемый proxy
не сводятся в один адрес: безопасное включение отказывается от такой конфигурации.
Существующий генератор не исполняет сторонний PAC: его URL сохраняется и возвращается,
но его правила не включаются в новый PAC. Полное объединение сторонних PAC требует
отдельного изменения генератора и отдельной проверки. Существующая схема общего PAC
также не обеспечивает разные правила fallback для сервисов с proxy и без proxy.

## Ограничения и ручная проверка в VM

- На рабочем Mac не проверялись реальные WinINet/SystemConfiguration, получение
  прав Authorization Services, Time Machine exclusion, NSIS, сон/пробуждение,
  updater и деинсталляция. Это обязательная проверка перед снятием Draft.
- При отказе прав SystemConfiguration сохранит запись для повторного восстановления.
  Полное завершение процесса не гарантирует немедленного восстановления: после
  SIGKILL/abort нужен следующий запуск или `--cleanup` от того же пользователя.
- У старых версий нет снимков глобальных HKCU/launchd переменных. Автоматически
  восстановить их прежнее значение невозможно; неизвестные следы остаются.
- UTF-16/невалидный UTF-8, повреждённый JSONC, дублирующиеся управляемые ключи,
  не-объект вместо env, неоднозначные маркеры, символические ссылки и профиль без
  конечного перевода строки безопасно отклоняются. Текст/кодировка не конвертируются.
- Уже открытый терминал хранит своё унаследованное окружение до перезапуска.
  TZ ограничен конфигами ИИ и управляемыми профилями; часы ОС не меняются.
- Уже существовавшие безопасные блоки внутри точных маркеров могут восстанавливаться
  как baseline. Опасный старый PowerShell else не возвращается при миграции.
- Созданный файл конфигурации может остаться пустым JSON-объектом после очистки.
  Текст незатронутых ключей и комментарии сохраняются; пробельные строки вокруг
  вставленных/удалённых полей могут остаться.
- WinINet и файловые конфиги не предоставляют общий атомарный CAS со сторонними
  программами. Повторное чтение сужает окно гонки; одновременная запись точно между
  проверкой и заменой остаётся ограничением. SystemConfiguration дополнительно
  блокирует сессию записи и сохраняет соседние поля из свежей конфигурации.
- Если удалить журнал или весь профиль пользователя до очистки, исходные значения
  восстановить невозможно. Деинсталлятор намеренно не удаляет остаточный журнал.
- Снятие Draft требует Windows/macOS VM со снимками: свои PAC и HTTP/HTTPS/исключения,
  разные сервисы и пустые значения, Throne TUN/HTTP, внешние изменения во время работы,
  enable/disable x3, --cleanup x2, kill между intent/write/confirmation, restart,
  сон/пробуждение, добавление/удаление сервиса, updater, uninstall без журнала,
  чужие HKCU/launchd TZ/LANG и PowerShell-профили с BOM/CRLF/UTF-16, отказ прав.

## Безопасные проверки

Запуск приложения и полный `cargo test` на рабочем Mac не выполняются.
Разрешённый фильтр: `cargo test --manifest-path src-tauri/Cargo.toml --lib sysproxy::`.
Его тесты используют Fake backend, временные файлы и преобразование plist в памяти;
реальные сетевые настройки, реестр, launchctl, networksetup и tmutil не вызываются.
В unit tests путь журнала подменён временным каталогом на поток; настройка ACL/backup
исключена из тестового исполнения. Полный набор можно скомпилировать через `--no-run`.

Матрица T01–T22 покрыта на уровне модели/файлов, но mock-тесты не заменяют VM.
NSIS проверяется статически; системный integration test запускается только в VM
с явным `--ignored`. Файлы 12 аудитов, NetworkGuard, ИИ-маршрутизации и UI не изменены.
